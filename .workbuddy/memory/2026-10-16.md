## 重要教训：契约变更必须用真实入口冒烟验证

- **测试全绿 ≠ 可用**。单 JD 收紧后 211 passed，但 `uv run python main.py` 直接失败 `Invalid configuration fields: max_jobs`——本地 `.env` 的 `MAX_JOBS=20` 违反新 `le=1`。
- 同批漏改还有 `main.py` 三处 `create_initial_state(..., max_jobs=...)`（参数已被移除，会抛 TypeError）。
- 根因：**所有测试都显式构造 `Settings`、直接调用 API/Graph，从不经过 CLI，也不读 `.env`**；配置模板与入口脚本是测试盲区。
- 已修复：`main.py` 删三处传参 + `--run-workflow` 改 `nargs=2` + `--selected-job-index` 加 `choices=[0]`；`.env` 与 `.env.example` 的 `MAX_JOBS` 改 1；新增 env 模板守卫测试（反向验证过：改回 20 会失败）。
- 遗留环境注意：沙箱下 pytest 的默认 basetemp（`%TEMP%`）不可访问，需 `--basetemp=.pytest-tmp`；`scripts/check_release.py` 需 `PYTHONPATH=.` 才能 import `app`。
